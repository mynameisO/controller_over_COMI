# COMI training on RunPod L40

`runpod_training.py` replaces the original `runpod_training.ipynb` workflow.
It runs in the foreground and displays loss, progress, and peak CUDA memory in
the terminal. No background supervisor, PID files, or separate training log files
are created. Checkpoints, trainer state, and metrics remain available for resume.

Use Linux, Python 3.10–3.12, and a driver compatible with CUDA 12.4. The entrypoint
installs PyTorch 2.6.0/cu124 in `/workspace/comi-venv-l40`; pinned dependencies are
in `requirements-runpod.txt`. L40 has 48 GB VRAM and BF16 support; see
[NVIDIA specifications](https://www.nvidia.com/en-us/data-center/l40/).
Actual memory requirements must be checked on your Pod.

## Run commands in the Pod terminal

Copy/extract this repo under `/workspace/comi`, then run these one at a time:

```bash
cd /workspace/comi
python3 runpod_training.py setup
python3 runpod_training.py prepare
python3 runpod_training.py check
python3 runpod_training.py smoke
python3 runpod_training.py smoke-eval
python3 runpod_training.py train
python3 runpod_training.py eval
```

Start full training after smoke training/inference succeed. No environment
activation or notebook is required. `prepare` copies bundled converted HotpotQA
data when available, otherwise downloads/converts it, and verifies manifest hashes.
The first model load downloads Qwen. GPU preflight runs actual BF16 CUDA kernels.

For long jobs, run training inside `tmux new -s comi`. Detach using Ctrl+B then D;
return using `tmux attach -t comi`. Logs stay in the terminal. Stopping the Pod
stops the process; run the same train command to resume its latest checkpoint.

## Defaults and overrides

- Qwen/Qwen3-4B-Instruct-2507, encoder 8 layers and fusion 1 layer fully tuned.
- Full decoder backbone with LoRA rank 128, alpha 32, dropout 0.05.
- One GPU, BF16, batch 1, accumulation 8, gradient checkpointing, PyTorch SDPA.
- Merge size 16, context segments of 4,096 tokens; context is not truncated.
- AdamW, learning rate 1e-5, 10,000 steps (about 0.884 epoch).
- Loss printed every 10 steps, evaluation every 1,000, saving every 2,000.
- One retained intermediate checkpoint plus final model. W&B is disabled.

```bash
# Approximately one epoch on one GPU at effective batch 8:
python3 runpod_training.py train --max-steps 11306

# Process smaller segments, retaining the whole context:
python3 runpod_training.py train --segment-size 1024

# Forward extra training/model arguments:
python3 runpod_training.py train -- --learning_rate 2e-5

# Explicit optimizer/scheduler resume:
python3 runpod_training.py train -- \
  --resume_from_checkpoint /workspace/comi-output/hotpotqa-l40/checkpoint-8000
```

Paths can be changed with `--workspace`, `--venv-dir`, `--data-dir`, `--output-dir`,
and `--smoke-output-dir`. For a new experiment use a new output directory. Keep
the same training configuration when resuming. `--restore_from` loads only model
weights; it does not restore optimizer state.

## Disk and output

Before smoke/full training the script checks for 50 GiB free on the output
filesystem. This is a planning reserve for one retained checkpoint, not an exact
measurement. Override explicitly with `--min-free-disk-gib` after measuring your
requirements. More retained checkpoints require more disk. Dependencies, base
model cache, and data need additional space; budget persistent storage accordingly.

```text
/workspace/comi-data/hotpotqa/                # Prepared data
/workspace/hf-cache/                         # Base model cache
/workspace/comi-output/hotpotqa-l40-smoke/    # Smoke model/checkpoint
/workspace/comi-output/hotpotqa-l40/          # Full model and latest checkpoint
```

`smoke-eval` reads `checkpoint-3`. Evaluation uses full validation and writes
answer EM/F1 under `eval_result/`; supporting-fact/joint scores are not included.
Full context lengths vary, so passing smoke does not guarantee every example fits
in VRAM. The legacy `nq_` prefix on result filenames is retained.

Save model/config/tokenizer files and the latest checkpoint before deleting the
Pod. Use the repo COMI loader; these are full COMI weights, not a standalone Qwen
checkpoint. Run CPU checks with `python -m pytest -q`.
